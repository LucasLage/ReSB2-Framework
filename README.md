# ReSB² framework Pipeline

This repository implements the ReSB² framework, a complete pipeline for processing Brazilian legislative bills, generating embeddings, training models, indexing in OpenSearch, and evaluating retrieval performance.

---

## **Pipeline Overview**

The pipeline performs the following steps:

1. **Data Processing**
   - Generate Câmara data using `CamaraDataGenerator`.
   - Preprocess ALMG proposition data using `AlmgDataPreprocessor`.
   - Generate ALMG dataset using `AlmgDataGenerator`.
   - Split the dataset into training and test sets (`split_save_data`).

2. **Model Training**
   - Masked Language Model (MLM) training.
   - Bi-Encoder training.
   - Cross-Encoder training.

3. **Indexing and Search**
   - Create an OpenSearch index for embeddings.
   - Index all processed propositions.
   - Support for external embedding indices (e.g., OpenAI embeddings).

4. **Evaluation**
   - Evaluate retrieval performance using different setups:
     - Bi-Encoder only
     - Cross-Encoder only
     - OpenAI embeddings
   - Compute metrics such as Recall@K and MRR@K.
   - Compare with baselines.

## Setup Instructions

### 1. Create a Python virtual environment and activate it

```bash
python3 -m venv pipeline_venv
source pipeline_venv/bin/activate  # Linux/macOS
# .\pipeline_venv\Scripts\Activate.ps1  # Windows PowerShell
```

### 2. Clone the repository

```bash
git clone https://github.com/LucasLage/ReSB2-Framework.git
cd ReSB2-Framework
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

## Dataset

The SB² Dataset used by this pipeline is publicly available on Hugging Face:

**https://huggingface.co/datasets/lucas-lage/SB2-Dataset**

The repository provides:

- **Raw legislative data** collected from the Legislative Assembly of Minas Gerais (ALMG) and the Brazilian Chamber of Deputies. This is the primary input consumed by the pipeline.
- **Preprocessed datasets** generated by the pipeline, including data used for continued pre-training (MLM) and supervised similarity training (Bi-Encoder and Cross-Encoder). These files are provided for convenience, reproducibility, and inspection purposes.

The pipeline starts from the raw legislative data and automatically performs the preprocessing steps, dataset generation, model training, indexing, and evaluation. The preprocessed datasets are not required to execute the pipeline, as they are generated internally during the data processing stage.

## Running the Pipeline

Run the complete pipeline with default arguments:

```bash
nohup python3 -u run_pipeline.py > ../log.txt 2>&1 &
```

---

## Arguments

| Argument                      | Description                        | Default                                                  |
| ----------------------------- | ---------------------------------- | -------------------------------------------------------- |
| `--base_model`                | Base BERT model                    | `jhu-clsp/mmBERT-base`                                   |
| `--contex_size`               | Context window size for bi-encoder | `1500`                                                   |
| `--open_ai_index`             | Name of OpenAI embedding index     | `proposicao_full_openai_large`                           |
| `--os_host`                   | OpenSearch host                    | `localhost`                                              |
| `--os_port`                   | OpenSearch port                    | `9200`                                                   |
| `--os_user`                   | OpenSearch username                | `admin`                                                  |
| `--os_password`               | OpenSearch password                | `pass`                                   |
| `--seed`                      | Random seed for reproducibility    | `42`                                                 |

## Output

A timestamped output directory is created:

```
../output_YYYY_MM_DD/
```

Subdirectories:

* `data/` – processed data and splits
* `mlm_output/` – trained MLM model
* `bi_encoder_output/` – trained bi-encoder model
* `cross_encoder_output/` – trained cross-encoder model
* `testing_result/` – testing result
